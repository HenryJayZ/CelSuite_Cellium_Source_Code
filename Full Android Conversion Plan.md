## 3. Asset Pipeline & Binary Asset Packing

### 3.1 Wallpaper & Icon Assets

* **Launcher Icon:** `icon.webp` is converted into an adaptive vector drawable + raster mipmap tree (`mipmap-hdpi`, `mipmap-xhdpi`, `mipmap-xxhdpi`, `mipmap-xxxhdpi`) placed in `app/src/main/res/`.
* **Background Wallpaper:** `cel_wallpaper.webp` is placed in `app/src/main/res/drawable/cel_wallpaper.webp`. In Compose, it is rendered using an edge-to-edge `Image(painterResource(R.drawable.cel_wallpaper), contentScale = ContentScale.Crop)`.

### 3.2 Avatar 1,520 Expressions: Binary Compaction Spec

* **Problem:** Loading 1,520 individual JSON files causes high file-handle overhead, asset extraction lags, and battery drain on Android's flash storage.
* **Solution (Desktop & Mobile Shared Binary Format):**
A desktop packaging script compiles the directory tree `Anim/{Gender}/*.json` into a single flat binary file: `expressions.celanim` (stored in Android `assets/expressions.celanim`).
* **Binary Format Specification:**
* **Header (16 bytes):** Magic `CELANIM\x01` (8 bytes) + Count (uint32) + TableOffset (uint32).
* **Index Table:** For each expression:
* `name_len` (uint8) + `name_utf8` (string)
* `gender` (uint8: 0=Female, 1=Male)
* `data_offset` (uint32)
* `data_length` (uint32)


* **Expression Data Payload:**
* Fixed parameters (packed floats/booleans): `blink_flags` (1 byte), `left_depth` (float16), `right_depth` (float16), `left_speed` (float16), `right_speed` (float16), `fade_opacity` (float16), `occlusion_offset` (float16).
* `point_count` (uint16)
* Points array: For each point, 5 bytes:
* `x` (uint16, stored as $x \times 10$ clamped to 0..6000)
* `y` (uint16, stored as $y \times 10$ clamped to 0..4000)
* `kind_and_side` (uint8: bit 7 = isLeft, bits 0-6 = kind enum index)






* **Unpacker Engine (`AvatarBinaryLoader.kt`):** Memory-maps `expressions.celanim` using `AssetFileDescriptor.createInputStream().channel.map(MapMode.READ_ONLY)`. Expression lookups are $O(1)$ directly from memory-mapped ByteBuffers without allocating garbage on the JVM heap.
* **Shared Pipeline Action:** The python generator script (`pack_avatar_binary.py`) will be added to `cellium/tools/` so the PySide6 desktop app can consume the exact same binary file.

## 4. The Cerebellium Dot-Matrix Avatar Engine

The avatar is strictly a **particle dot matrix**, never continuous polyline curves.

### 4.1 Particle Physics & Simulation Loop

Every active point $p_i$ has a live position $(x_i, y_i)$, target position $(tx_i, ty_i)$, target alpha $at_i$, current alpha $\alpha_i$, and feature phase $\phi_i$.

* **Physics Equations:**
1. **Spring Relaxation:**

$$x_{i} \leftarrow x_{i} + (tx_{i} - x_{i}) \cdot k$$


$$y_{i} \leftarrow y_{i} + (ty_{i} - y_{i}) \cdot k$$



where $k = 0.22$.
2. **Harmonic Breathing Bob:**

$$\text{bob} = \sin(t \cdot \text{period} \cdot 1000) \cdot \text{amp}$$


3. **Deterministic Mirrored Jitter (Brownian Noise Simulation):**

$$x_{i} \leftarrow x_{i} + \sin(t \cdot 7.3 + \phi_{i}) \cdot \text{shake}$$


$$y_{i} \leftarrow y_{i} + \cos(t \cdot 5.9 + \phi_{i} \cdot 1.31) \cdot \text{shake}$$



where $\phi_i$ is computed from CRC32:

$$\phi_i = \frac{\text{CRC32}(\text{kind} + ":" + \text{index}) \ \& \ \text{0xFFFF}}{\text{0xFFFF}} \times 2\pi$$


4. **Touch Repulsion Dynamics:**
When a touch point $(mx, my)$ is active with velocity $v > 1.2$:

$$\text{dist} = \sqrt{(x_i - mx)^2 + (y_i - my)^2}$$



If $0.1 < \text{dist} < 55.0$:

$$\text{force} = \left(1.0 - \frac{\text{dist}}{55.0}\right) \cdot \min(v \cdot 0.35, 6.0)$$


$$x_i \leftarrow x_i + \frac{x_i - mx}{\text{dist}} \cdot \text{force}$$


$$y_i \leftarrow y_i + \frac{y_i - my}{\text{dist}} \cdot \text{force}$$



Displacement clamped to $\le 28.0\text{px}$ from $(tx_i, ty_i)$.



### 4.2 Audio-Reactive Mouth Sync

* During speech playback, the audio stream outputs real-time normalized RMS energy:

$$\text{rms} = \sqrt{\frac{1}{N} \sum_{n=0}^{N-1} s[n]^2}$$


* Primitives of kind `stem`, `bottom_bar`, and `mid_bar` are dynamically modulated:

$$y_{\text{stem}} = ty_{\text{stem}} + (\text{rms} \cdot 18.0\text{px})$$


$$y_{\text{bottom\_bar}} = ty_{\text{bottom\_bar}} + (\text{rms} \cdot 12.0\text{px})$$



### 4.3 Multi-Touch Gesture Detection & Feedback

* **Tap:** Triggers an immediate double-blink sequence (`blink_now()`).
* **Stroke / Pan:** Displaces dots via repulsion physics, plays animalese purr chirps (`playAnimalesePurr()`), and sets mood to `love`.
* **Long-Press Interaction:**
* When a finger is held stationary for $> 150\text{ms}$, a circular radial progress ring draws around the touch point, filling from $0^\circ$ to $360^\circ$ over $500\text{ms}$.
* Upon completion ($500\text{ms}$), haptic feedback triggers (`HapticFeedbackType.LongPress`) and the Frosted Glass Mood Selector pops up at the finger coordinates.



### 4.4 Frame-Pacing Strategy

* **Foreground Focused (Chat / Studio / Live Call):** Driven by Compose `withFrameMillis` loop locked at 60 FPS.
* **Background Pet Mode (Floating Window):** Timer throttled to locked 30 FPS to reduce CPU/GPU draw and keep battery consumption $< 2.5\%$ per hour.

## 7. Voice Assistant, Audio & System Service Hooks

### 7.1 Bypassing the Persistent Green Mic Dot

* **Android Sandbox Rule:** Running an `AudioRecord` background service triggers a permanent green mic icon in the Android status bar.
* **Architecture:**
* Cel implements `VoiceInteractionService` and `VoiceInteractionSessionService`.
* Once the user sets Cel as the **Default Digital Assistant** in Android Settings, Android routes voice interactions through `HotwordDetectionService`.
* Audio streams directly through the sandboxed isolated audio pipe without keeping the system recording indicator permanently illuminated.



### 7.2 The Gemini-Style Floating Pill Overlay

* Triggered when the assistant is summoned via hardware shortcut, corner swipe, or "Okay Cel".
* Opens a lightweight, floating frosted bottom sheet (`AssistantPillOverlay`) on top of whatever app the user is using:
* Includes an interactive audio visualizer pill.
* `[+ Screenshot]` button: Captures screen content via `MediaProjection` or `VoiceInteractionSession.onHandleScreenshot()` and attaches it to the prompt.
* Voice transcript auto-types in real time.
* Tapping the expand icon expands the pill into full `LiveCallScreen`.



### 7.3 Multi-Engine Audio Pipeline

* **Online TTS (Default):** `EdgeTtsService` communicates directly over WebSocket to Microsoft's streaming endpoint, piping 24kHz raw PCM chunks directly into `AudioStreamPlayer`.
* **Offline Fallback TTS:**
* Level 1: Android native `TextToSpeech` engine (zero download, instant).
* Level 2: `KokoroTtsEngine`. An in-app download manager downloads the 85MB `kokoro-v1.0.fp16.onnx` and `voices.bin` on demand to app storage.


* **Noise Gate & Ambient Calibration:**
* Ports `noise_gate.py` to Kotlin.
* Records 2.8 seconds of ambient room noise, computes 50ms block RMS, and sets an adaptive noise threshold so air conditioners and fans do not trigger false turns.


* **Barge-In:** Explicitly disabled in V1 per specification to prevent audio feedback and false positives.

## 8. Agent Mode, Tools & Shizuku Privileged Execution

### 8.1 Execution Mode Selection & Shizuku Guide

* When the user enables Agent Mode in chat, a dialog prompts:
* **[Run in Sandbox]:** Low-privilege execution using standard Android Toybox utilities within app data directories.
* **[Use Shizuku ADB]:** Full system-level execution via ADB permissions (`UID 2000`).


* **Interactive Setup Wizard:** If Shizuku is selected but the daemon is not running or unbonded:
* Displays a visual step-by-step modal guide:
1. Install Shizuku from GitHub / Play Store.
2. Enable Developer Options & Wireless Debugging.
3. Pair port & start Shizuku.
4. "Grant Permission" button triggering `Shizuku.requestPermission()`.





### 8.2 Privileged Tool Execution Loop

* Executes via `dev.rikka.shizuku:api:13.1.5` and `dev.rikka.shizuku:provider:13.1.5`.
* Commands run via `Shizuku.newProcess(arrayOf("sh", "-c", command), null, null)`.
* Fully unconstrained agent access:
* Package operations (`pm install`, `pm uninstall`, `pm clear`).
* Activity management (`am start -n`, `am force-stop`).
* System property / Settings writes (`settings put global ...`, `settings put secure ...`).
* System telemetry (`dumpsys battery`, `dumpsys cpuinfo`, `dumpsys meminfo`).



### 8.3 Destructive Command Interceptor (`MobileCommandGuard.kt`)

* Every command string is audited before execution against high-risk regex patterns:
* Recursive wipes (`rm -rf /`, `rm -rf /sdcard/*`).
* Block device writes (`dd if=... of=/dev/block/...`).
* Root-level state tampering (`reboot`, `recovery`, `pm wipe`).


* If flagged, execution halts and pops an alert dialog:
* Displays full command and exact risk flags.
* Choices:
1. **Allow Once:** Executes this single command and resets.
2. **Allow Always (This Session):** Adds command hash to an in-memory session allowlist.
3. **Deny:** Aborts tool execution, returning `"User denied command execution"` to the model.

## 9. Mobile Local Inference (llama.cpp Architecture)

### 9.1 Hardware Tiering & Safety Matrix

* **< 4GB System RAM:**
* Local GGUF execution is disabled by default in the UI with an informative banner.
* An override switch in Settings allows users to enable it at their own risk ("Unrestricted Mode").


* **4GB System RAM (Baseline Galaxy A03):**
* Default Context: strictly `1024` tokens.
* Recommended Model Tier: 0.5B – 1.5B (e.g., Qwen2.5-Coder-0.5B / 1.5B Q4_K_M, SmolLM2-1.7B).


* **6GB System RAM:**
* Default Context: `2048` tokens.


* **8GB+ System RAM:**
* Default Context: `4096` tokens.



### 9.2 Execution Engine & Low-Memory Killer (LMK) Defenses

* Uses precompiled `libllama.so` linked through native JNI bindings.
* Local inference executes inside a dedicated foreground worker thread using a background coroutine on `Dispatchers.IO`.
* Context tokens are pruned aggressively when buffer limits approach 85% to prevent native `OOM` process kills.
